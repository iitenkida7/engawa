Map JSON (MapDef) spec

A map JSON only says what goes where. The app draws every part itself (desks, chairs, trees: world/map-art.ts), and the only looks a map picks are a floor pattern and a colour index. Every figure on this page is the real map, exported with the app's own renderer (buildMapCache), with the JSON rects drawn on top.

conventions

      
Coordinates are tiles, origin at the top left

    

    

      
      

        
    
          
  • Coordinates are absolute map positions, never relative to a building or room.
    • 
          
  • c grows to the right and r grows downward. [0, 0] is the top-left tile.
    • 
          
  • A point (TilePos) is [c, r]; a rect (TileRect) is { "c", "r", "w", "h" }.
    • 
          
  • All values are integers. w and h are at least 1.
    • 
          
  • Any tile nothing is placed on is outdoor grass.
    • 
        


"plants": [[9, 14]]
"rooms":  [{ "id": "ceo", "c": 9, "r": 9, "w": 6, "h": 4, … }]

      

    

  


  

    

      
top level

      
Keys (all required)

      
A kind you don't use is still written, as an empty array [].

    

    

      

        
KeyTypeMeaning

        
          
version1Format version. The current build reads only 1.

          
cols / rowspositive intMap width and height in tiles. The office is 52×43.

          
buildingsBuilding[]Buildings with an outer wall.

          
roomsRoom[]Walled rooms. Each room is one call zone.

          
desksDesk[]One desk with one chair.

          
teamAreasTeamArea[]Wall-less shared rugs. Everyone on one is in the same call.

          
loungesLounge[]Wall-less café call zones.

          
plants[c, r][]Potted plants (one tile).

          
pondsTileRect[]Ponds.

          
treesTree[]Outdoor trees.

        
      

    

  


  

    

      
buildings

      
Buildings: the wall is the rect's own edge

    

    

      
      


{ "c": 8, "r": 8, "w": 36, "h": 27,
  "doors": [[8, 21], [43, 21], [8, 22], [43, 22]] }

        
    
          
  • The outermost ring of tiles inside the rect becomes the wall; everything inside it is floor.
    • 
          
  • Each tile in doors turns a wall tile back into floor, making an entrance.
    • 
          
  • A door must sit on the wall (the rect's edge). A door anywhere else is an error.
    • 
        

      

    

  


  

    

      
rooms

      
Rooms: the rect is the interior, the wall goes outside it

      
The opposite of buildings: a room's rect does not include its wall. The wall ring is stamped one tile outside it, so the room plus its wall must fit on the map.

    

    

      
      


{ "id": "meeting-1", "kind": "meeting",
  "name": { "ja": "会議室1", "en": "Meeting room 1" },
  "c": 29, "r": 9, "w": 4, "h": 4,
  "doors": [[30, 13], [31, 13]],
  "table": { "c": 30, "r": 10, "w": 2, "h": 2 },
  "floor": { "pattern": "crosshatch", "color": 5 } }

        

          
            
idNon-empty string, unique across rooms, teamAreas and lounges. The server groups calls by this id, so two areas sharing one would merge into a single call through the wall.

            
kindexec / meeting / oneonone / booth。Only meeting rooms get a whiteboard and a cabinet, start cameras on the light q simulcast layer, and count for the recording reminder.

            
nameDisplay name as { ja, en }.

            
doorsTiles on the wall ring (one tile outside the rect).

            
tableSolid meeting table, drawn with chairs around it.

            
floorOptional. The rug look (see the palette below).

          
        

      

    

  


  

    

      
desks

      
Desks: (c, r) is the middle of the desk

    

    

      
      


{ "c": 14, "r": 17, "facing": "south",
  "rug": { "pattern": "chevron", "color": 2 } }
{ "c": 14, "r": 18, "facing": "north",
  "rug": { "pattern": "chevron", "color": 2 } }
{ "c": 31, "r": 25, "facing": "south" }

        
    
          
  • A desk three tiles wide (c-1 to c+1) is centred on (c, r).
    • 
          
  • facing is the way the seated person faces. With "south" the chair is one tile above the desk; with "north" it is one tile below.
    • 
          
  • With rug, a 3×3 rug centred on the chair is laid down. Leave it out for no rug.
    • 
          
  • The office stacks a south desk above a north desk to make face-to-face islands.
    • 
        

      

    

  


  

    

      
teamAreas · lounges

      
Call zones without walls

      
Everyone standing inside either rect joins one call. Unlike rooms, no wall is stamped.

    

    

      
      


"teamAreas": [{ "id": "team-area",
  "c": 30, "r": 23, "w": 9, "h": 6,
  "floor": { "pattern": "vstripe", "color": 2 } }]

"lounges": [{ "id": "cafe-left",
  "name": { "ja": "ラウンジ1", "en": "Lounge 1" },
  "c": 2, "r": 24, "w": 6, "h": 5,
  "floor": { "pattern": "stripe", "color": 8 } }]

        
    
          
  • As with rooms, id is unique across all zones.
    • 
          
  • A lounge needs a display name; a teamArea does not.
    • 
          
  • Colour index 8 is reserved for lounges.
    • 
        

      

    

  


  

    

      
plants · ponds · trees

      
Plants, ponds and trees

    

    

      
      


"plants": [[9, 14], …],
"ponds":  [{ "c": 44, "r": 2, "w": 5, "h": 4 }],
"trees":  [{ "c": 39, "r": 2, "size": 1, "variant": 1 },
           { "c": 48, "r": 7, "size": 2, "variant": 1 }, …]

        
    
          
  • A plant is a point [c, r]. The office uses them indoors, in room corners and along corridors.
    • 
          
  • A tree's size is 1 or 2, with (c, r) as its top-left tile.
    • 
          
  • A tree's variant (0 or 1) picks its look.
    • 
          
  • Trees go on grass only. A tree overlapping a building or room is rejected by tilemap.
    • 
        

      

    

  


  

    

      
floor · rug

      
Floor palette: { pattern, color }

      
A room's floor, a desk's rug, and a teamArea's or lounge's floor all pick from the same palette. color is an index into the app's FLOOR_THEMES (world/floor-styles.ts).

    

    

    
Swatches use the app's own pattern code; each cell shows 2×2 tiles. none is a plain rug.

  


  

    

      
assertMapDef

      
Checks at load time

      
TypeScript types cannot guard a JSON file, so the map is checked when it loads. A mistake stops loading at once with an error that names the spot (for example invalid map data: room 'meeting-1' door 0: tile [4,7] is not on its wall). A map that passes is frozen so nothing can modify it.

    

    

      

        
Stops with an error

        
    
          
  • version other than 1
    • 
          
  • A missing top-level array
    • 
          
  • Non-integer positions or sizes; w or h below 1
    • 
          
  • Points or rects off the map (rooms are checked with their wall)
    • 
          
  • Doors not on their wall
    • 
          
  • Unknown kind or pattern; color out of range
    • 
          
  • name that is not { ja, en } strings
    • 
          
  • Empty or duplicate zone ids
    • 
          
  • facing other than south / north; a bad tree size or variant
    • 
          
  • Trees off the grass (caught by tilemap)
    • 
        

      

      

        
Not checked (layout judgement)

        
    
          
  • Rooms, desks or zones overlapping each other
    • 
          
  • Whether a table fits inside its room
    • 
          
  • Whether rooms and desks sit inside a building
    • 
          
  • Whether a door leads anywhere walkable
    • 
        

        
Check these on screen and in the snapshot test when you change the map.

      

    

  


  

    

      
maintenance

      
What else to update when the map changes

    

    

      
    
        
  • If you change cols / rows, update the server's MAP_WIDTH=2600 / MAP_HEIGHT=2150 (server/src/logic.ts) and the client's core/types.ts by hand. Both assume 52×43 tiles at 50px.
    • 
        
  • The tile grid built from the map is pinned by snapshots in __tests__/tilemap-split.test.ts. After an intended change, update them with bun test -u.
    • 
        
  • Room behaviour depends on kind, not on the id. The id only identifies the call group.
    • 
        
  • This page's map image (docs/map/office-map.webp) and the office.json embedded in the page are snapshots. When the map changes, replace both, in this page and in the Japanese one. To export the image, open the dev server (http://localhost:5173 after make up) and run this in the browser console:
    • 
      


const c = (await import('/src/world/map-art.ts')).buildMapCache(1);
c.toBlob((b) => {
  const a = document.createElement('a');
  a.href = URL.createObjectURL(b);
  a.download = 'office-map.webp';
  a.click();
}, 'image/webp', 0.9);
