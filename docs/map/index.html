マップ JSON（MapDef）仕様

マップ JSON は「どこに何を置くか」だけを書くデータです。机や椅子、木の絵はアプリ側（world/map-art.ts）が描き、JSON で選べる見た目は床柄と色番号だけです。このページの図はすべて、アプリ本体の描画コード（buildMapCache）で書き出した実際のマップに、JSON の枠を重ねたものです。

いまの office.json

実物のマップを JSON から描く

現在の maps/office.json（52×43 タイル）から、アプリが実際に描くマップです（アバターと部屋名の札は除く）。マウスを乗せる（スマホではタップ）と、そのタイルを決めている JSON の要素と枠が出ます。「JSON の枠」をオンにすると、要素ごとの矩形を色分けで重ねます。

このタイル
[c, r]
  • マップの上にカーソルを乗せてください。

      

    

  


  

    

      
共通の約束

      
座標は「タイル」、左上が原点

    

    

      
      

        
    
          
  • 座標はマップ上の絶対位置で、建物や部屋からの相対位置ではありません。
    • 
          
  • c は右へ、r は下へ増えます。[0, 0] が左上のタイルです。
    • 
          
  • 点（TilePos）は [c, r]、矩形（TileRect）は { "c", "r", "w", "h" } と書きます。
    • 
          
  • 値はすべて整数です。w・h は 1 以上です。
    • 
          
  • 何も置かれていないタイルは、すべて屋外の芝生になります。
    • 
        


"plants": [[9, 14]]
"rooms":  [{ "id": "ceo", "c": 9, "r": 9, "w": 6, "h": 4, … }]

      

    

  


  

    

      
トップレベル

      
キーの一覧（すべて必須）

      
使わない要素も、空配列 [] で書きます。

    

    

      

        
キー型意味

        
          
version1フォーマットのバージョン。いまのビルドは 1 だけ読みます。

          
cols / rows正の整数マップの幅と高さ（タイル数）。office は 52×43。

          
buildingsBuilding[]外壁つきの建物。

          
roomsRoom[]壁で囲まれた部屋。1 部屋が 1 つの通話ゾーン。

          
desksDesk[]机 1 台と椅子 1 脚の組。

          
teamAreasTeamArea[]壁のない共有ラグ。乗っている人全員が同じ通話に入る。

          
loungesLounge[]壁のないカフェの通話ゾーン。

          
plants[c, r][]植木（1 タイル）。

          
pondsTileRect[]池。

          
treesTree[]屋外の木。

        
      

    

  


  

    

      
buildings

      
建物: 壁は矩形の「内側」の外周

    

    

      
      


{ "c": 8, "r": 8, "w": 36, "h": 27,
  "doors": [[8, 21], [43, 21], [8, 22], [43, 22]] }

        
    
          
  • 矩形のいちばん外側の 1 タイルが外壁になり、その内側が床になります。
    • 
          
  • doors に書いた外壁のタイルが床に戻り、出入口になります。
    • 
          
  • ドアは外壁（矩形の縁）の上にある必要があります。縁から外れたドアはエラーです。
    • 
        

      

    

  


  

    

      
rooms

      
部屋: 矩形は「中身」、壁はその外側

      
建物とは逆で、部屋の矩形は壁を含みません。壁はその外側 1 タイルに置かれるので、壁まで含めてマップ内に収まる必要があります。

    

    

      
      


{ "id": "meeting-1", "kind": "meeting",
  "name": { "ja": "会議室1", "en": "Meeting room 1" },
  "c": 29, "r": 9, "w": 4, "h": 4,
  "doors": [[30, 13], [31, 13]],
  "table": { "c": 30, "r": 10, "w": 2, "h": 2 },
  "floor": { "pattern": "crosshatch", "color": 5 } }

        

          
            
id空でない文字列。rooms・teamAreas・lounges の全体で重複不可です。サーバーはこの id で通話をまとめるので、重複すると壁越しに 1 つの通話になります。

            
kindexec / meeting / oneonone / booth。meeting だけ、ホワイトボードと棚が置かれ、カメラを軽い q レイヤから受信し始め、録画リマインドの対象になります。

            
name{ ja, en } の表示名。

            
doors壁の輪（矩形の外側 1 タイル）の上のタイル。

            
table通れない会議テーブル。周りに椅子が描かれます。

            
floor任意。ラグの柄（後述のパレット）。

          
        

      

    

  


  

    

      
desks

      
デスク: (c, r) は机の中央

    

    

      
      


{ "c": 14, "r": 17, "facing": "south",
  "rug": { "pattern": "chevron", "color": 2 } }
{ "c": 14, "r": 18, "facing": "north",
  "rug": { "pattern": "chevron", "color": 2 } }
{ "c": 31, "r": 25, "facing": "south" }

        
    
          
  • (c, r) を中心に、横 3 タイル（c-1〜c+1）の机が置かれます。
    • 
          
  • facing は座る人の向きです。"south" なら椅子は机の 1 つ上、"north" なら 1 つ下に置かれます。
    • 
          
  • rug を付けると、椅子を中心に 3×3 のラグが敷かれます。省略するとラグなしです。
    • 
          
  • office では、south と north を上下に並べて向かい合わせの島にしています。
    • 
        

      

    

  


  

    

      
teamAreas · lounges

      
壁のない通話ゾーン

      
どちらも、矩形の上に乗った人がまとめて 1 つの通話に入ります。部屋と違って壁は置かれません。

    

    

      
      


"teamAreas": [{ "id": "team-area",
  "c": 30, "r": 23, "w": 9, "h": 6,
  "floor": { "pattern": "vstripe", "color": 2 } }]

"lounges": [{ "id": "cafe-left",
  "name": { "ja": "ラウンジ1", "en": "Lounge 1" },
  "c": 2, "r": 24, "w": 6, "h": 5,
  "floor": { "pattern": "stripe", "color": 8 } }]

        
    
          
  • id は部屋と同じく、全ゾーンで重複不可です。
    • 
          
  • lounge には表示名 name が必要です。teamArea には不要です。
    • 
          
  • 色番号 8 はラウンジ用の専用色です。
    • 
        

      

    

  


  

    

      
plants · ponds · trees

      
植木・池・木

    

    

      
      


"plants": [[9, 14], …],
"ponds":  [{ "c": 44, "r": 2, "w": 5, "h": 4 }],
"trees":  [{ "c": 39, "r": 2, "size": 1, "variant": 1 },
           { "c": 48, "r": 7, "size": 2, "variant": 1 }, …]

        
    
          
  • 植木は点 [c, r] で置きます。屋内（office では部屋の隅や廊下）で使います。
    • 
          
  • 木の size は 1 か 2 で、(c, r) が左上になります。
    • 
          
  • 木の variant（0 か 1）は見た目の種類です。
    • 
          
  • 木は芝生の上にしか置けません。建物や部屋に重なると、tilemap がエラーにします。
    • 
        

      

    

  


  

    

      
floor · rug

      
床柄パレット: { pattern, color }

      
部屋の floor、デスクの rug、teamArea と lounge の floor は、同じ形式でパレットから選びます。色はアプリの FLOOR_THEMES（world/floor-styles.ts）の番号です。

    

    

    
見本はアプリの柄の描画コードと同じもので、1 マス＝2×2 タイル分です。none は柄なしの無地ラグです。

  


  

    

      
assertMapDef

      
読み込み時の検査

      
JSON は TypeScript の型では守れないため、読み込み時に検査します。誤りがあると、場所の名前付きのエラー（例: invalid map data: room 'meeting-1' door 0: tile [4,7] is not on its wall）ですぐに止まります。検査を通ったマップは書き換えできないよう凍結されます。

    

    

      

        
エラーで止まるもの

        
    
          
  • version が 1 以外
    • 
          
  • トップレベルの配列が欠けている
    • 
          
  • 整数でない座標・サイズ、1 未満の w・h
    • 
          
  • マップからはみ出す点や矩形（部屋は壁を含めて判定）
    • 
          
  • 壁の上にないドア
    • 
          
  • 未知の kind・pattern、範囲外の color
    • 
          
  • name が { ja, en } の文字列でない
    • 
          
  • ゾーン id の空文字・重複
    • 
          
  • facing が south / north 以外、木の size / variant の不正値
    • 
          
  • 芝生以外に置かれた木（tilemap が検出）
    • 
        

      

      

        
検査しないもの（レイアウトの良し悪し）

        
    
          
  • 部屋同士・机同士・ゾーン同士の重なり
    • 
          
  • table が部屋の内側に収まっているか
    • 
          
  • 部屋やデスクが建物の内側にあるか
    • 
          
  • ドアの先が通路につながっているか
    • 
        

        
これらは、マップを変えたときに実際の画面とスナップショットで確認します。

      

    

  


  

    

      
運用メモ

      
マップを変えるときに一緒に直すもの

    

    

      
    
        
  • cols / rows を変えたら、サーバーの MAP_WIDTH=2600 / MAP_HEIGHT=2150（server/src/logic.ts）とクライアントの core/types.ts も手で合わせます。現在は 52×43 タイル × 50px が前提です。
    • 
        
  • マップから作られるタイルの並びは、__tests__/tilemap-split.test.ts のスナップショットで固定されています。意図して変えたら bun test -u で更新します。
    • 
        
  • 部屋の種類による振る舞いは id ではなく kind で決まります。id は通話のまとまりの識別にだけ使われます。
    • 
        
  • このページのマップ画像（docs/map/office-map.webp）と、ページに埋め込んだ office.json は書き出した時点のコピーです。マップを変えたら両方を差し替えます。画像は、開発サーバー（make up 後の http://localhost:5173）を開いたブラウザのコンソールで次を実行して保存します。
    • 
      


const c = (await import('/src/world/map-art.ts')).buildMapCache(1);
c.toBlob((b) => {
  const a = document.createElement('a');
  a.href = URL.createObjectURL(b);
  a.download = 'office-map.webp';
  a.click();
}, 'image/webp', 0.9);
